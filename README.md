# スイーツ店舗 在庫確認（締め作業用）

営業終了後の在庫確認を iPad で行い、LINE に貼り付ける報告テキストを作るための Web アプリです。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 本体。この1ファイルだけで動きます（外部ライブラリ・通信なし） |
| `sw.js` | 任意。`index.html` と同じ場所に置くと、通信できないときも起動できるようになります |
| `.claude/launch.json` | 開発中のプレビュー用。運用には不要です |

## 公開先

- アプリの URL：https://wsty-gif.github.io/zaiko/
- リポジトリ：https://github.com/wsty-gif/zaiko （公開リポジトリ。GitHub Pages で配信）
- 更新するとき：`index.html` を直して commit・push すると、数分〜10分ほどで公開先が新しい版になります。iPad は、次に通信できる状態で開いたときに新しい版を読み込みます。入力データと設定は消えません。
- データ（在庫数・現金・設定）は iPad の中にだけ保存され、GitHub には送られません。

## iPad への設置

1. `index.html` と `sw.js` を、HTTPS で配信できる場所に置きます（例：GitHub Pages、Cloudflare Pages、Netlify、店舗の社内サーバー）。
   - HTTPS で開くと、クリップボードへの自動コピー（Clipboard API）とオフライン起動が有効になります。
   - iPad では、ファイル App から HTML を直接開いて Safari で動かす方法が限られるため、Web 上に置く方法をおすすめします。
2. iPad の Safari で開き、共有ボタン →「ホーム画面に追加」。
3. 以後はホーム画面のアイコンから起動します。
   - Safari のタブで開いた場合と、ホーム画面から開いた場合とでは、データの保存場所が別になります。どちらか一方に決めて使ってください（ホーム画面から開く方をおすすめします）。

## 画面構成

| 画面 | 内容 |
|---|---|
| 開始 | 今日の日付と「在庫確認を開始」。前日以前の在庫確認を終了し忘れているときは「今日の在庫確認を開始／〇月〇日の続きを入力する」を選びます |
| 在庫確認（メイン） | 上部：日付・入力済み件数／全件数・進捗バー・表示切替（一覧／保管場所別）・購入必要数・設定。<br>絞り込み：すべて／食材／備品／金庫／未入力／購入必要。<br>下部：「未入力を順に入力」「報告を作成」 |
| 数量入力（モーダル） | 商品名・保管場所・メモ・数量表示・単位ボタン・発注目安と購入必要数・数字パッド・「保存して閉じる」「保存して次へ」 |
| 報告の確認 | 報告テキストのプレビュー、未確認項目・単位違いの項目の警告、コピー（報告／購入必要品のみ）、「今回の在庫確認を終了する」 |
| 設定 | 商品・備品／保管場所／単位／バックアップ の4つのタブ |

縦向きでは入力モーダルが画面下から出る1列のレイアウト、横向きでは左に表示・単位、右に数字パッドを並べた2列のレイアウトになります。

## 毎日の使い方

1. ホーム画面のアイコンから開く
2. 「在庫確認を開始」を押す
3. 「未入力を順に入力」を押す（または一覧のカードをタップ）
4. 入力画面には前回の数量が最初から入っています。同じならそのまま、違えば数字パッドで入れ直すか「＋1」「−1」で直す（2回目以降は単位も最初から選ばれています）
5. 「保存して次へ」で次の未入力の項目へ進む。在庫がなければ「在庫なし（0）」を1回押すだけで保存して次へ進みます
6. 金庫の紙幣・硬貨は枚数、「その他 小銭」は金額（円）を入れる
7. 「報告を作成」→ 内容を確認
8. 「報告をコピー」（必要なら「購入必要品のみコピー」）
9. LINE を開いて貼り付け、送信
10. アプリに戻り「今回の在庫確認を終了する」→ 入力した数量は次回の「前回の数量」として残り、設定もそのまま残ります

### 入力のルール

- **前回の数量の引き継ぎ**：前回の在庫確認で入力した数量が、カードに「前回 3箱」と薄く表示され、入力画面にも最初から入っています（「前回 11/25」の印付き）。保存するまでは「未入力」のままで、「保存して次へ」を押すとその数量で確定します。「×」で閉じた場合は確定しません。報告や購入必要の判定には、今回確定した数量だけを使います。
- **未入力と 0 は別物**です。未入力は「未入力（グレー）」、0 は「0／入力済（グリーン）」と表示されます。金庫の未入力は報告で「未確認」になります。
- **小数**は小数点以下2桁まで入力できます（例：0.5袋）。紙幣・硬貨は整数のみで、小数点のキーが無効になります。
- **単位**：単位が未設定の項目は、最初に選んだ単位がその項目の単位として記憶され、次回から自動で選ばれます。設定画面からいつでも変えられます。
- **修正**：カードをタップすると、今の数量が色付きで表示されます。そのまま数字を押すと置き換わります。「未入力に戻す」で入力を取り消せます。
- **飛ばす**：数量が空のときは、右下のボタンが「スキップして次へ」になります。
- **複数の保管場所**：1つの商品に複数の保管場所を設定すると、場所ごとに入力欄（タブ）が出ます。同じ単位なら合計し、違う単位（例：4個＋1袋）は合算せずに並べて表示します。
- 入力途中で確認ダイアログは出しません。確認が出るのは、未確認があるままコピーするとき、在庫確認を終了するとき、設定の削除・復元・初期化のときだけです。

### 保管場所別の表示

上部の「保管場所別」に切り替えると、保管場所ごとにまとめて表示し、「保存して次へ」も保管場所の順（設定の並び順）に進みます。冷蔵庫内をすべて確認してから棚上へ、という回り方ができます。場所が変わるときは「次の保管場所：棚上」のように知らせます。

## 購入必要数の計算

```
購入必要数 ＝ 最大値（発注目安 − 現在の在庫数, 0）
```

- 発注目安が未設定の項目は、不足の判定をしません。在庫が発注目安を下回ったとき（同じ数のときは含めません）に購入必要とします。
- 在庫の単位と発注目安の単位が違うときは、数を出さずに「単位の確認が必要」と表示します。下回っているか判定できないため、LINEの報告には含めず、報告画面で別に知らせます。
- 在庫が 0 のときは単位に関係なく 0 なので、発注目安そのものが購入必要数になります。
- 複数の保管場所がある項目は、すべての場所を入力し終えてから判定します。
- 現金は購入必要数の計算に含めません。

## 報告テキスト

LINE に送る報告は、**在庫が発注目安を下回っている項目（一覧でオレンジの枠の項目）と、金庫内の現金だけ**です。

```
【締め作業・在庫報告】
2026年11月25日

■購入必要品
マラサダ冷蔵：購入 6個（在庫 4個／目安 10個）
フルグラ：購入 1.5袋（在庫 1.5袋／目安 3袋）

■金庫内現金
一万円札：2枚
五千円札：1枚
千円札：5枚
500円玉：4枚
100円玉：10枚
その他 小銭：350円

合計：33,350円
```

- 発注目安以上ある項目、発注目安が未設定の項目、単位が違って判定できない項目は載せません。
- 下回っている項目がないときは「購入必要品なし」と表示します。
- 金庫に未入力があるときは、その行を「未確認」とし、「合計：28,350円（未確認の項目を除く）」と書きます。
- 未入力の項目があるときや、単位が違って判定できない項目があるときは、報告画面とコピー前の確認で知らせます（LINEの文章には載せません）。
- 「購入必要品のみコピー」は、■購入必要品の部分だけをコピーします。
- コピーは Clipboard API → `execCommand('copy')` の順に試し、成功したときだけ「コピーしました」と表示します。どちらも失敗したときは、全文を選択して手動でコピーする画面を開きます。
- コピーしただけでは在庫確認は終わりません。「今回の在庫確認を終了する」を押すと、入力した数量を「前回の数量」として残し、次回の在庫確認に備えます（まだコピーしていない場合は、確認画面でその旨を表示します）。

## データの保存

すべて iPad のブラウザ内（localStorage）に保存します。サーバーやデータベースは使いません。

| 種類 | 保存先キー | 内容 | 消えるとき |
|---|---|---|---|
| 設定（永続） | `sweetsZaiko.master.v1` | 商品・備品、カテゴリ、単位、発注目安、保管場所、並び順、メモ、有効／無効 | 設定画面で初期化したときのみ |
| 今回の入力 | `sweetsZaiko.session.v1` | 日付、数量・単位（保管場所ごと）、現金、コピー済みの時刻 | 「今回の在庫確認を終了する」または「今日の在庫確認を開始」を押したとき（中身は「前回の数量」へ移ります） |
| 前回の数量 | `sweetsZaiko.prev.v1` | 項目・保管場所ごとの、いちばん最近確定した数量・単位とその日付 | 消えません（次の在庫確認を終えると新しい数量に置き換わります。その回に入力しなかった項目は、それより前の数量が残ります） |
| 表示の状態 | `sweetsZaiko.ui.v1` | 絞り込み、一覧／保管場所別、設定のタブ | — |
| 表の反映済みの印 | `sweetsZaiko.seed` | 店舗で記入した表の内容を反映したか（版番号） | — |

- 入力のたびに保存するため、途中で再読み込みしても入力は残ります。
- 在庫確認を終了し忘れて日付が変わっても、入力は消しません。次に開いたとき「〇月〇日の在庫確認が終了していません」と表示し、「今日の在庫確認を開始」（前日の数量を引き継いで始める）か「〇月〇日の続きを入力する」を選べます。前日の報告をコピー済みなら「今日の在庫確認を開始」が大きいボタンになり、確認なしで始まります。入力が1件もなければ、そのまま今日の日付に切り替えます。
- 日付をまたいで作業したときは、上部の日付をタップして報告の日付を変更できます（未来の日付は選べません）。
- 過去の在庫確認の履歴は残しません（残すのは「前回の数量」だけです）。
- 設定画面「バックアップ」から、設定をファイル（JSON）またはテキストで保存・復元できます。当日の入力は含みません。

### すでに使っている iPad への反映

この版を初めて開いたときに1回だけ、表の内容（単位・保管場所・発注目安・購入先・名前の変更・砂糖の無効化）を今の設定へ反映します。

- 入力途中の数量は消さず、新しい保管場所へ移します。
- 自分で書いたメモは残し、空のメモにだけ購入先を入れます。自分で追加した項目には触れません。
- 単位・保管場所・発注目安は表の内容で置き換えます。反映した後に設定画面で変えた内容は、その後も置き換えません（バックアップから復元した設定も同じです）。
- その後に店舗から受けた訂正（名前「アサイー原料」、チョコソースの在庫5）は、表の内容を反映済みの iPad にも、その2点だけを1回反映します。

## 検証結果

### 検証した環境

- Claude デスクトップアプリ内蔵のブラウザ（Chromium）、`http://localhost:8765`
- 画面サイズを iPad 相当に変えて表示（820×1180 / 1180×820、768×1024 / 1024×768、744×1050、1133×660、1024×1366 / 1366×1024）
- 操作は画面上のボタンをクリックして行いました（マウスのクリックで、タッチ操作そのものではありません）
- 加えて、LINE報告の変更と前回の数量の引き継ぎは、**WebKit 18.2（iPad の Safari と同じエンジン）で iPad（第7世代）を再現**し、公開URL（https://wsty-gif.github.io/zaiko/）を**タッチのタップ操作**で動かして確認しました（Playwright を使用。実機の Safari そのものではありません）

## 端末を限定したい場合（提案）

HTML やブラウザの判定では、特定の iPad 以外からのアクセスを確実には防げません（端末の情報は偽装できます）。厳密に限定する場合は、配信側で制限します。

| 方法 | 内容 | 向いている場合 |
|---|---|---|
| **クライアント証明書（mTLS）** | 配信サーバーの前段（例：Cloudflare Access）で、iPad にインストールした証明書を持つ端末だけを通す | 厳密に端末を限定したい場合。今回の構成（静的ファイル）にそのまま使えるため、最もおすすめです |
| **MDM で管理** | Apple Business Manager と MDM で iPad を管理し、証明書の配布や VPN 接続を管理端末に限定する | 店舗が増える、端末を入れ替える予定がある場合 |
| **店内ネットワーク限定** | 店舗の Wi-Fi の中だけで配信する | 外部に公開したくない場合。オフライン起動（sw.js）と組み合わせる |
| **ログイン（Basic 認証・メールの確認コード）** | 人で制限する。端末の制限ではありません | 手軽さを優先する場合 |

あわせて iPad の「アクセスガイド」を使うと、iPad をこのアプリだけに固定できます（他の端末からのアクセスを防ぐものではありません）。
